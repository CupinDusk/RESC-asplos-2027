WHAT WAS BUILT (answers Round-9 "producer-consumer forwarding cache, not
coherence" by making intra-cluster multi-writer genuinely coherent):
  (A) FALSE-SHARING SYNC-MERGE  -- CLUSTER_MW_MERGE state + per-sector written
      mask; a 2nd same-cluster (same-GPC) writer of disjoint sectors merges
      (0 new fabric messages, rides existing write-through); consumer MW_MERGE
      read is forbidden a single-owner whole-line forward (serve-path invariant).
  (B) ATOMIC OWNER-TOKEN HANDOFF -- one migrating token (reuses XCWL {gpc,addr});
      a peer atomic sends one UpgradeReq over SM-to-SM; owner downgrades
      EM->INVALID transiting FORWARD (makes the dead F-state + invalidate edge
      LIVE); requester installs EM; gated by g_xcwl_gen. One hop/ownership change.

CORRECTNESS SPINE: GPGPU-Sim cache blocks are TAG-ONLY; the functional simulator
performs all loads/stores/atomic-RMW against global memory (write-through => L2
is always a byte-accurate merge). The CLUSTER_* machine is a pure timing/routing
+ coherence-bookkeeping overlay, so bit-identity to a correct reference is
STRUCTURAL. Consequence (reported honestly): the whole-line-LWW ablation (arm4)
CANNOT corrupt the checksum in a tag-only sim; its necessity is shown instead by
WRITEBACK TRAFFIC (arm4 whole-line vs arm2 per-sector).

NOTES (honest)
- Path A (false-sharing reduction): arm2 mw_merge_entries=64 (MW_MERGE fires),
  bit-identical; arm4 whole-line-LWW sector_writebacks=1120 vs arm2 per-sector=280
  = 4x traffic -> per-sector mask necessity shown via WRITEBACK TRAFFIC (not a
  fabricated checksum failure; tag-only sim => value always L2-correct).
  arm2 cycles 10706 <= arm3 10706 < arm1 10939.
- Path B (atomic reduction): arm2 atomic_upgradereq=56, forward_downgrades=56,
  atomic_local_owner=8 (one first-touch/cluster), new_fabric_msgs=56 (one hop per
  ownership change, never broadcast), bit-identical. EM->FORWARD->INVALID dead
  edge now LIVE. arm2 7102 cyc ~= arm3 7061 (+0.6% honest token overhead).
- Secondary stencil (mw_stencil): bit-identical across ALL four arms, but the
  per-sector MW_MERGE never fires (mw_merge_entries=0 on every arm). This is
  HONEST and structural, not a bug or an omission:
    * Diagnosis (RESC_MW_DEBUG=2): the merge hook IS reached on every stencil
      write (24 merge-entry attempts for 1 cluster x 2 iters), but ALL 24 exit
      via "no-peer" -- at merge-probe time no same-cluster peer holds the shared
      line in a WRITER state (EM/SM/MW_MERGE). Layout is correct (all 8 ranks'
      halo words share one registered 128B line, 0xf00000000), so it is not a
      registration/layout problem.
    * Root cause: the stencil is single-writer-per-line at any instant. Each rank
      writes only its OWN word once per epoch; the epoch's cluster.sync self-
      invalidates marked lines, so a co-writer's copy is never simultaneously
      resident when the next rank writes. The write-through neighbor reads take
      the read-share path (7 read-share hits observed), leaving peers in SHARED,
      not a writer state. There is thus no genuine concurrent same-line writer
      for the merge to bind to.
    * One workload-only salvage attempt (add a residency-establishing neighbor
      peek before each write, mirroring the reduction) was tried and STILL
      produced 0 merges + bit-identical -- confirming the stencil is structurally
      single-writer-per-line in this sim's residency model. No sim source was
      changed for this.
  CONCLUSION: The canonical Path-A (false-sharing merge) demonstration is the
  reduction FORM=1 kernel above (mw_merge_entries=64, per-sector vs whole-line
  4x writeback). The stencil stands as an additional BIT-IDENTICAL correctness
  case; its merge genuinely should not (and does not) fire.
