(d) ARM1 BIT-DIVERGENCE — the correctness hook (off-sim, data-carrying)
--------------------------------------------------------------------------------
WHY OFF-SIM: GPGPU-Sim cache_block_t is TAG-ONLY (no data array; gpu-cache.h).
Every load/store/atomic runs in the FUNCTIONAL model against global shadow memory,
so an in-sim checksum is byte-correct even for a BROKEN coherence policy
(gpu-cache.cc:3319-3323 says this). In-sim BITIDENTICAL=1 for ALL arms — that is
STRUCTURAL, not a correctness proof. Staleness is a VALUE property, shown on real
data by a model that replays the exact residency + gen-window logic
(resc_gen_live, gpu-cache.cc:407-419). Same methodology as the MW correctness
argument (correctness/CORRECTNESS_ARGUMENT.md, modelcheck_output.txt).

Workload: a REUSED cluster-scoped comm buffer (bounded ring, LAG+1 slots) that a
producer republishes each epoch — the normal cluster idiom (mw_stencil halo /
mailbox), NOT a fresh malloc per epoch. Golden = value(prod, epoch-LAG).

  correctness/arm1_divergence 8 32 <LAG> 128 :
  LAG | arm0 refetch | arm1 UNSAFE     | arm2 DeNovo G=2 | arm3 RESC G=LAG+1
   1  | mism=0 CORRECT| mism=29696 WRONG| mism=0 CORRECT  | mism=0 CORRECT (served 31744)
   2  | mism=0 CORRECT| mism=27648 WRONG| mism=0 CORRECT  | mism=0 CORRECT (served 30720)
   4  | mism=0 CORRECT| mism=23552 WRONG| mism=0 CORRECT  | mism=0 CORRECT (served 28672)
  arm1 returns STALE values (pinned L1 copy, no self-invalidate) once the ring
  wraps: mism>0 = INCORRECT. arm0/arm2/arm3 bit-correct. NOTE at LAG>=2: arm2
  (DeNovo single keep-valid interval) is CORRECT but served=0 — it CANNOT serve
  the lagged read from peer L1, it must refetch from L2; arm3 serves it (30720).
  FINDING: the fast unsafe-residency upper bound (arm1) is BIT-WRONG. Coherence
  (arm2 self-invalidate OR arm3 gen-ring) is what buys CORRECTNESS atop residency.

--------------------------------------------------------------------------------
(f) PRE-REGISTERED GATE — which holds
--------------------------------------------------------------------------------
Prereg SUCCESS rule: arm3 beats arm2 by >=1.3x in a defensible non-strawman
  regime (real concurrent writers / deep pipeline where arm2 provably
  serializes/refetches).
Prereg NULL rule: arm3-over-arm2 stays modest (<1.3x) OR the regime is a
  sim-fidelity artifact.

MEASURED best arm3-over-arm2 = 1.033x (3.3%, pipeline LAG=2); MW = 1.000 / 1.006.
ALL well below 1.3x.  => **NULL holds. Scissors CONFIRMED.**

The regime where arm2 provably fails IS defensible and non-strawman (served2=0
for LAG>=2 is a real structural inability of a single keep-valid interval), and
arm3 IS faster there — but only by ~3%, because the served read-share saves a
fixed comm-latency delta (peer-L1 195 vs L2 242 cyc) that is small relative to
whole-kernel time; the in-order ClusterSim models no async compute/copy overlap
that would amplify it (reported honestly, not claimed).

HONEST VERDICT (as pre-registered): RESC's LARGE numbers (occupancy 1.44-1.88x
here, legality up to 2.64x) are PLACEMENT — any safe L1-resident scheme (arm2)
gets them; the coherence design point adds ~0%. RESC's genuinely unique value is
(a) CORRECTNESS: the fast unsafe overlay (arm1) is bit-WRONG (stale reads once a
reused comm buffer wraps; concurrent multi-writers lose writes/updates); arm2/arm3
are bit-correct; and (b) GENERALITY: LAG>=2 pipelines and concurrent multi-writers
that a correct simpler baseline (arm2) provably cannot serve from L1 (served2=0)
— arm3 serves them, correctly, ~3% faster. The honest thesis is legality-led
"legal + general L1 residency (correct where the unsafe overlay is wrong, general
where DeNovo serializes)", with a coherence-design-point contribution that is
STRUCTURAL (expresses a class DeNovo/hLRC cannot) but performance-MODEST in this
in-order simulator.
