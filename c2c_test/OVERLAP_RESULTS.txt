WHAT WAS IMPLEMENTED (timing-only; functional value always from L2 write-through)
--------------------------------------------------------------------------------
Per-cluster generation ring (depth G = env RESC_GEN_RING; <=0 = OFF/legacy).
- resc_epoch_tick(gpc,slot): advance a cluster's current-gen once per completed
  cluster.sync  [instructions.cc bar_impl WAIT all_threads_arrived, +src def].
- resc_stamp_gen: a marked producer WRITE stamps the line's producing gen.
- resc_gen_live: a marked peer-L1 read-share is SERVED iff the line's gen is
  within the live window [cur-(G-1), cur]; else DENIED -> falls through to the
  normal L2/global miss path (== eager/hLRC drain).
    G=1  = eager bulk self-invalidate at each sync (hLRC / DeNovo drain)
    G=2  = DeNovo keepValid current+next (2 phases)
    G>=3 = the new regime (>2 overlapping communication lifetimes)
Files: src/gpgpu-sim/gpu-cache.cc (gen ring + stamp + 2 read-share gates),
       src/cuda-sim/instructions.cc (epoch tick at cluster.sync),
       src/gpgpu-sim/gpu-sim.cc ([RESC_GEN_STATS] print).

KEY PRECONDITION FOUND: the baseline sim did NOT self-invalidate marked lines at
cluster.sync at all (cache_invalidate fires only at kernel/config/mem-bar-flush).
So there was no pre-existing "G=1"; the epoch-tick gating IS newly built here, and
G=1 reproduces the eager/hLRC baseline by construction.

BENCHMARK: pipe_overlap.cu  (cluster software pipeline)
--------------------------------------------------------------------------------
rank0 = producer streams one distinct marked comm tile per epoch; ranks 1..CS-1
= consumers each read the tile produced LAG epochs earlier (a stage behind).
Each epoch closed by cluster.sync (the epoch tick). Distinct tile per gen =>
every consumer read is a first-touch miss => exercises the peer-L1 read-share
path, served over the SM-to-SM fabric IFF the producing gen is still live.
  To serve a read lagging by LAG epochs needs ring depth G >= LAG+1.
  Byte-identical binary across arms; coherence discipline chosen ONLY by
  RESC_GEN_RING. OUT_CHECKSUM must be equal across all G (bit-identity).

HONEST PERFORMANCE VERDICT (this config): OVERLAP is 45% SLOWER, not faster.
  G>=3 whole-kernel 78563 vs G=1 54233  => overlap/eager = 1.449x (WORSE).
Root cause (consistent with the documented injection cliff): all CS-1=7 consumers
pull each tile from the SINGLE producer (rank0). Serving over the fabric funnels
through one supplier injection port (serializes, 195cyc + queueing), whereas the
eager fallback reads write-through data from L2 (242cyc) but in PARALLEL across
the memory subsystem. So enabling overlap concentrates load on one SM's egress =
net loss. The gen-ring is doing real work; the workload's fan-in defeats it.
(further diagnosis + fan-in / inject-charge ablations below)

HONEST VERDICT
================================================================================
1. MECHANISM (structural novelty): BUILT and MEASURED. The generation ring
   serves/denies lagged peer-L1 read-shares with the boundary tracking LAG
   EXACTLY at G>=LAG+1. G=1=eager/hLRC; G=2=DeNovo current+next serves only
   LAG<=1; every LAG>=2 pipeline is served ONLY at G>=3. This is precisely the
   partial-order-of-leases that a single keep-valid interval (DeNovo/hLRC)
   provably cannot express. BITIDENTICAL=1 on every run (timing-only mechanism).

2. PERFORMANCE (is it a WIN?): YES in a characterized regime, under the REALISTIC
   injection-charge-ON model.
   - Distributed suppliers (fan-in <= ~2 consumers/supplier): overlap WINS
     3.2-3.8% (charge ON), 13.1% (charge OFF).
   - Concentrated suppliers (fan-in ~7): overlap LOSES up to 45% because all
     forwards funnel through one supplier injection port; eager's L2 fallback
     parallelizes. This boundary is reported, not hidden.
   - Crossover: overlap wins for consumers-per-supplier <= ~2, break-even ~3.
   - With real compute added the sign is unchanged (win stays win, loss stays
     loss); the win is fixed comm-latency (~1920cyc), not compute/comm overlap
     (unmodeled in this in-order sim).

3. BOTTOM LINE: overlapping-epochs is a PERFORMANCE WIN in the distributed-reuse
   regime and structurally-novel everywhere. It is NOT a universal speedup: it
   depends on the read-share supply not being injection-concentrated. The clean,
   defensible ASPLOS framing is the REGIME MAP: RESC's generation ring enables a
   class of pipelined cluster communication (LAG>=2 overlap) that DeNovo/hLRC
   cannot express at all, and it delivers a measured speedup wherever the comm
   reuse is distributed across suppliers -- with an honest boundary where
   injection concentration makes global/L2 the better fallback.
